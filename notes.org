* Stage 2
- We make our first compromise and this comes from our first insight.
- Many workflow systems often force you to express control flow declaratively because the orchestrator needs to figure out what to run. Temporal has an insight - we don't need the orchestratior to know the whole DAG, it just needs a function that can tell it what the *next* thing to do
- So here we use an async interator function and rather than running code like print and sleep directly we yield back a command object for it, then the workflow runs that
- This doesn't help anything yet, we're just compromisin'

* Stage 3

* Stage 4
- Now, when the workflow starts, we start running the workflow and as it gives us back each command we check that against our recorded history. This we find out how far the workflow ran
- The compromise of determinism
  - We had to get rid of the random sleep, we'll bring that back later
